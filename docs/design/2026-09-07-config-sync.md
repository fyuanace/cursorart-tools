## 背景信息

思源不同步 `/conf` 与自定义主题。需要先落到 `data` 再走云端同步。

## 当前方案

- 缓存：`/data/storage/petal/cursorart-tools/config-sync`（在插件 petal 目录内，才能随官方同步走）
- 覆盖云端：先 `performSync` 拉云端基线 → 清空缓存 → 把当前设置和主题拷入缓存 → 把有效文件列表写入 `manifest.json` 并删掉列表外残留 → 再 `performSync` 上传。此过程不写 `/conf/appearance/themes/`。
- 插件必须实现空的 `onDataChanged`：思源把 `petal/<插件名>/` 的文件变更当成插件存储更新；不覆盖此钩子就会默认卸载再加载，覆盖时拷贝主题树（上百次 putFile）会把顶栏/侧栏注入拆掉再装上。应用云端配置只走「下载云端配置」按钮。
- 下载云端：未开同步则中止；直接同步（不先删缓存，避免空目录被当成本地更新推到云端）→ 若 manifest 有文件列表则删掉缓存里列表外的残留 → 对缓存里有的每个自定义主题，先删掉 `/conf/appearance/themes/<name>` 中除 `.git` 外的内容，再从缓存拷入 → 再 `importConf` 导入设置。若缓存无包，拷贝旧 `petal/fhelper/config-sync`
- 设置页开头写明前提：须先启用思源官方云端同步或 S3 同步。使用方法只写用户步骤：A 端点「覆盖云端配置」并等待同步完成；B 端点「下载云端配置」并等待同步完成；程序提示重启后重启，再在设置中手动选择主题。清空缓存、导出 conf、写入应用目录等写在「原理」。设置窗口和重启确认都走思源 `zIndex` 递增，后打开的叠在上面。

## 其他模块引用约束

下载不要先删缓存。覆盖时先同步再删缓存再拷贝。不要把 daylight / midnight 写入缓存。

## 工程师测试验收方法

配置同步页可打开缓存文件夹；覆盖/下载按钮在已开同步时可用。点「覆盖云端配置」时顶栏按钮、侧栏 dock、爱心不应反复消失再出现。「正在同步」在完成后应自动换成结果提示并消失，不要一直挂着。先开插件市场再开设置，设置应在市场之上；设置里再弹出重启确认，确认应在设置之上。
